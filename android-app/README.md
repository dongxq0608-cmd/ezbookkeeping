# EzBook · ezBookkeeping 安卓客户端

一个原生 Android 客户端（Kotlin + Jetpack Compose），直接调用你已部署的
[ezBookkeeping](https://github.com/mayswind/ezBookkeeping) 服务端 REST API。
不依赖 WebView，数据仍然只存在你自己的服务器上。

## 已实现功能

| 模块 | 说明 |
| --- | --- |
| 服务器配置 | 首次启动填写服务地址，支持子路径（`https://host/ezbookkeeping`）与 HTTP/HTTPS |

| 账单列表 | 按月浏览、上下月切换、收入/支出/转账筛选、按日分组小计、下拉刷新；**默认只展示最近一周，滚动到底部自动加载上一周（跨月时自动拉取上一个月）**；左滑单笔可露出红色「删除」按钮，点击后删除；长按可「复制 / 复制（含时间）」 |

| 账户明细 | 点击账户进入该账户（含子账户）明细：默认最近一周，滚动到底部按周向前加载，跨月时自动拉取上一个月，整月无账单即停止；**左滑单笔可露出红色「删除」按钮，点击后才删除** |

```bash
export JAVA_HOME=~/Library/Java/jdk-17.0.20.1+1/Contents/Home

export PATH="$JAVA_HOME/bin:$PATH"

./gradlew assembleDebug
```

## 首次使用

1. 打开 App，填写服务地址，例如 `https://book.example.com`
   （部署在子路径则填 `https://book.example.com/ezbookkeeping`，**不要**加 `/api`）
2. 点「连接并继续」，App 会请求 `{地址}/healthz.json` 探活
3. 输入 ezBookkeeping 的账号密码登录

## 服务端注意事项

1. **HTTPS 与 root_url**
   若走反向代理 + HTTPS，请把服务端 `conf/ezbookkeeping.ini` 的
   `[server] root_url` 配成对外地址，否则服务端生成的绝对资源地址会不正确：

   ```ini
   [server]
   protocol = https
   domain = book.example.com
   root_url = %(protocol)s://%(domain)s/
   ```

   反代场景还需把反代网段加入 `[security] trusted_proxy_ips`，否则客户端 IP 识别错误会影响限流。

2. **登录限流**
   `[security] max_failures_per_ip_per_minute` / `max_failures_per_user_per_minute`
   默认都是 5，连续输错会返回错误码 200018，App 会提示稍后再试。

3. **两步验证**
   若账号开启了 2FA，登录会先返回临时 token（5 分钟有效），App 会弹出动态验证码输入框，
   再调用 `/api/2fa/authorize.json` 换取正式 token。

4. **明文 HTTP**
   `AndroidManifest.xml` 中保留了 `android:usesCleartextTraffic="true"`，方便局域网
   `http://192.168.x.x:8080` 调试。若只使用 HTTPS，可以移除该属性以收紧安全策略。

5. **登录状态保持（token 有效期）**
   服务端 `[security] token_expired_time`（默认 2592000 秒 = 30 天）决定 token 寿命，
   `token_min_refresh_interval`（默认 86400 秒 = 1 天）决定多久之后才允许换发新 token。
   客户端每次启动 / 回到前台都会调用 `tokens/refresh.json` 主动续期（本地按 20 小时节流），
   续期成功后有效期再顺延 30 天——**只要 30 天内打开过一次 App，就不需要重新登录**。
   反过来说：token 一旦过期，服务端会直接拒绝续期（过期 token 无法用于刷新），此时只能重新登录。
   若希望容忍更长的闲置间隔，可把服务端 `token_expired_time` 调大，例如
   `7776000`（90 天）；客户端本地也会解析 JWT 的 `exp`，过期时直接进登录页，
   不会带着废 token 反复请求。

## 客户端实现要点（对接踩坑记录）

- 鉴权头格式是 `Authorization: bearer <jwt>`（**必须**带 7 字符前缀 `bearer `）
- 交易类接口必须带 `X-Timezone-Offset`（UTC 偏移分钟，东八区 = 480），否则返回 200008
- 服务端 ID 字段在 JSON 中都是**字符串**（`id`、`categoryId`、`sourceAccountId`…），
  请求体里也必须传字符串
- 交易金额是 **×100 的整数**（`1234` = 12.34）；账户 `balance` 是**「×100 的整数」转成的字符串**
  （`"234560"` = 2345.60），注意它已经是分，**不要再乘 100**
- `transactions/list/by_month.json` 一次性返回整月数据（无分页）；追加 `account_ids` 可按账户
  过滤，且服务端会自动展开该账户的子账户
- 服务端在**创建/刷新 token 时把请求的 `User-Agent` 原样存下来**，网页端「设备与会话」用
  ua-parser-js 解析这段 UA 得出设备类型与机型；OkHttp 默认的 `okhttp/4.x` 解析不出任何信息，
  会显示成 web + Unknown Device。客户端因此按 Android WebView 的经典 UA 格式上报
  （机型 + `Build.VERSION.RELEASE` + `Build.ID` + `Version/4.0 Mobile Safari`），末尾附加
  `EzBook/<版本号>` 便于识别；不带 Chrome 标识，网页端会显示为
  「机型 (Android Browser 4.0)」，与真实浏览器会话区分开
- 机型名优先取厂商系统属性里的市场名（`ro.product.marketname`、`ro.vendor.oplus.market.name`、
  `ro.config.marketing_name` 等），其次取系统设置里的“设备名称”，都没有才退回
  `Build.MANUFACTURER + Build.MODEL`；这样国产 ROM 上显示的是 Redmi K70 这类宣传名，
  而不是 `23113RKC6C` 这类入网认证型号
- `transaction/categories/list.json` 返回的是**按类型分组的字典**
  （`{"1":[...],"2":[...],"3":[...]}`），不是数组
- 登出是 `GET /api/logout.json`，且不在 `/api/v1` 下
- `tokens/refresh.json` 有最小刷新间隔（默认 1 天），可能返回**没有 `newToken`** 的结果，
  此时继续沿用旧 token，不算失败
- 错误响应带真实 HTTP 状态码，业务错误码在 body 的 `errorCode` 中
  （202001–202006 / 202012 表示需要重新登录）

## 已知限制

- 账单列表一次拉取整月数据，账单量极大（单月数千条）时首屏会偏慢
- 账户明细与交易日历的月份数据按月拉取：账户明细滚到底部才请求上一个月，跨很多个月需多次请求
- 交易日历按「天」聚合，单元格金额使用紧凑格式（`1.2万` / `1.5亿`），不显示角分
- 暂不支持账单图片附件、账户/分类/标签的新增与编辑（请在网页版操作）
- 暂不支持多币种折算，汇总按原币种数值直接相加
- 统计口径为「按月 + 客户端聚合」，与服务端报表在跨时区边界上可能有细微差异
